# Requirements (PRD)

A PRD makes the **case for an experience**: what changes for the person learning the
regulation, or the agent consulting it, and why it is worth building. It is not a task list
and not a design.

- How it is built, with alternatives, lives in an [RFC](../rfc/index.md).
- The decision, in a few lines, lives in an [ADR](../adr/index.md).

## What gets a PRD

Work where the **user-value argument** needs to be made: a view by role, the MCP answers an
agent gets, the page for one act. Plumbing (the record schema, the EUR-Lex pull, the CI gate) is
an RFC or an ADR. The test: if the "Why this is a PRD" sentence in the header is hard to write,
the work belongs elsewhere.

## Format

`PRD-NNN-short-slug.md`, numbered sequentially, never renumbered. Copy `PRD_TEMPLATE.md` from
this directory and read the notes at its bottom first.
